0 · The one thing that governs everything

Your YC story rests on two claims. The code says:

  1. The persistent World State is NOT yet wired into the agent loop. The FSM validator, the DB tables, and the "World State" REST view are three disconnected pieces. The pentest agent never reads or writes the state tables.
  2. DDQN / reinforcement learning does not exist in code — zero lines, anywhere. It is a design concept only.

Neither is fatal. But presented as implemented, a due-diligence reviewer finds the gap in ~15 minutes and loses trust in everything else. This plan makes claim #1 true before July 27 and never makes claim #2 at all.

1.2 The described agent loop does not exist yet

The cycle Query State → Select Action → Execute → Validate → Update State → Record Transition → Re-plan is not implemented:

  • No world_state_query / world_state_update agent tool exists.
  • Planner does not query state before acting; executor does not write state/transitions after acting.
  • No pre-execution gate, no duplicate-action prevention.
  • No credential entity/store; no cross-subtask credential reuse.
  • findings_extract.go = on-demand LLM extraction, not a deduplicated persistent store.
  • attackpath.go = paths computed on the fly from Graphiti at request time; not persisted; needs Neo4j.
  • Authorization = a UI tab, not scope-as-state enforcement. The evidence column exists but nothing writes it.
